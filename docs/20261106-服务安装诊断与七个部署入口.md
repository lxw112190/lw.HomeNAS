# 服务安装诊断与七个部署入口

用户反馈同一部署包在本机能安装，在另一台 Windows 10 教育版上以管理员身份安装时返回 `Create service failed, Win32_Service code 8`，且没有运行日志。

## 已知证据与原因边界

错误发生在 WMI `Win32_Service.Create` 返回后、启动 EXE 之前，因此没有 `data/logs/service.log` 符合执行顺序。微软将返回值 8 定义为通用未知失败，不能据截图断言是教育版不支持、缺运行库、端口冲突或账号策略。参考：[Win32_Service.Create 返回值](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/create-method-in-class-win32-service)。

读取了用户指定的 [lw.PPOCR.OpenCVDNN Windows 部署脚本](https://github.com/lxw112190/lw.PPOCR.OpenCVDNN/tree/main/deploy/windows)。借鉴其直接使用 Windows 服务控制接口和异常恢复设置，保留本项目的虚拟服务账号和目录权限设计。没有切换为 LocalSystem，也没有自动覆盖、删除既有服务。

## 最终改动

- 按用户最终要求只保留7个BAT：install-service、start-service、stop-service、restart-service、uninstall-service、open_firewall、remove_firewall。前5个采用连字符，防火墙沿用下划线；不增加菜单。
- 安装统一跟随 config/server.json，allow_insecure_lan 默认 true，不再区分两份安装脚本。旧服务上的显式参数可通过 Configure 去除，详见[部署说明](../deploy/README.md)。
- 新增 service-native.cs，由 PowerShell Add-Type 加载，通过 Unicode OpenSCManagerW/CreateServiceW 创建自动服务，虚拟账号密码传真正的 NULL。错误保留具体 Win32 代码与操作名，避免只得到 WMI 通用代码8。
- 创建成功后配置 SID、5秒/15秒失败重启和 ACL，再启动服务。后续失败保留已创建服务，供用户检查。
- 管理脚本在服务创建之前记录 deploy/logs/service-install.log；目录不可写时回退到 TEMP/lw.HomeNAS-deploy，窗口报告路径。记录 UTC、阶段、系统/PowerShell、路径和错误，不保存配置正文、密码、令牌或原生程序输出。达到1MiB轮转，保留3份历史。
- 前台及密码操作不采集 transcript；JSON解析失败只输出通用提示，避免解析器把带初始密码的配置原文写入日志。
- package/copy-runtime显式列出部署文件，排除本地日志；完整包验收同步检查7个BAT、原生助手及日志排除。发布CI加入诊断脚本回归。

## 验证范围

本机已验证PowerShell解析、7个入口、配置/HTTP/HTTPS计划、三种非SCM启动拒绝、两种防火墙计划；安装诊断10项检查覆盖创建前日志、失败阶段、退出码、轮转、临时目录回退、配置密码不泄露、原生助手编译及具体错误码保留。HTTP批处理另验证默认计划、参数冲突及非管理员拒绝。

没有在开发机实际安装/卸载服务，没有改ACL或防火墙，没有运行目标Win10教育版。上述检查不能证明新原生安装路径已在故障电脑解决问题。需在目标机应用脚本后以管理员执行install-service.bat；若仍失败，收集窗口显示的具体Win32错误码和安装日志，继续定位。旧WMI版本的14项真实安装记录不能代替本轮原生安装验收。

本轮仅部署脚本、测试及文档更新，未改NasServer二进制或APK，不递增APK版本。独立脚本补丁不等于重新发布完整CI部署包。

## r2：收到具体错误1783后的处理

用户在故障机应用r1后确认管理员权限、64位PowerShell5.1，CreateServiceW返回1783（0x6F7）。[微软错误表](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1700-3999-)将其定义为RPC_X_BAD_STUB_DATA。参数数量、宽字符串、DWORD、指针和虚拟账号NULL密码声明已按[官方CreateServiceW接口](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-createservicew)复核，未发现签名不匹配；当前仍未确定目标机根因，不能据此要求重装系统或关闭防火墙。

r2只在原生调用抛出1783时检查服务是否已存在。仅当OpenServiceW明确返回1060（不存在）后，调用Windows系统目录的sc.exe再创建一次；路径、账号、自动启动和服务类型保持一致，虚拟账号不传password=。存在同名服务、无法确定存在状态或其他原生错误均不重试，也不自动采用或删除已有服务。sc.exe同样会访问SCM，不能保证绕过系统端故障；双失败时记录两条路径并保持安装失败。

sc.exe使用ProcessStartInfo且UseShellExecute=false，不经过cmd或PowerShell原生参数二次拼接。Windows参数转义通过真实无害argv回显程序验证，覆盖中文、空格、括号、引号、尾反斜杠和&/%字符。安装函数使用测试专用适配器执行原函数体，覆盖原生成功不重试、1783单次重试保留身份、双失败日志、非1783不重试以及RPC失败后已存在服务的拒绝分支。

r2本机16项诊断回归及服务/防火墙计划检查通过；未实际创建服务、未更改ACL或防火墙，故障机实测仍待反馈。脚本补丁r2保留7个BAT，源代码和打包入口同步更新。

## r3：双路径1783后的范围诊断

用户在目标机复测r2，原生CreateServiceW与系统sc.exe均返回1783。兼容调用未解决问题，不能继续把它当作单一PowerShell调用故障处理，也不能断言Windows已损坏。未采用关闭防火墙、重装系统或自动切换正式服务身份的建议。

新增diagnose-service.ps1，不增加BAT。默认只读记录系统/PowerShell、RpcSs/DcomLaunch/RpcEptMapper/Winmgmt/BFE/MpsSvc状态、advapi32/sechost/rpcrt4/sc.exe版本和最近2小时最多12条SCM警告/错误；不读取NAS配置或媒体。报告保存在忽略的deploy/logs，临时目录为备用，返回实际路径。

显式 `-ProbeCreation` 模式需管理员权限，分别创建虚拟账号和LocalService的GUID临时服务。服务启动类型为Disabled，二进制为系统cmd.exe的无害exit命令，不调用StartService。成功创建后仅通过该次返回的句柄请求DeleteService并关闭句柄；不会按名称删除、启动或接管任何已有服务。失败/清理码及随机名称均保留在报告，未把删除请求成功等同于所有观察者句柄都已关闭。

账号对照用于缩小范围：仅虚拟账号失败提示进一步检查账号创建路径，两者都失败提示进一步检查SCM/RPC或系统拦截环境。两种结果都不能独自确证具体根因。正式NAS的安装身份和r2逻辑未自动改变。

本机20项非安装诊断检查、8份PowerShell及7个BAT/服务/防火墙计划通过，含两个账号的独立探测计划、PlanOnly无操作、默认只读报告实际生成；没有在开发机执行创建探测。目标电脑的对照测试需由用户执行后反馈JSON。r3是诊断补丁，不宣称已修复该机的1783。

## 目标机后续结果

用户在目标电脑执行DISM ScanHealth未发现组件存储损坏，SFC verifyonly发现完整性冲突；随后SFC scannow报告成功修复损坏文件。按重启后复测流程，用户反馈服务安装成功。未取得具体受损文件清单，记录为该机修复后的实测结果，不推断所有1783的根因相同。
