# Web回收站彻底删除与播放页编译修复

本次沿用尚未发布的1.0.1/code16/nativeApi9，不覆盖公开的1.0.0，也没有提交或推送仓库。

## 使用

管理员登录Web，资料库切换“回收站”，在单个文件卡片点“彻底删除”，输入四个字“彻底删除”并确认。普通成员仍可恢复自己删除的文件，不显示彻底删除。只删除回收站中指定的项目，不提供一键清空或活动资料库直接永久删除。

成功后删除电脑原件、缩略图及来源/文件夹/图集关联，清除图集封面引用，历史上传任务标记ORIGINAL_PURGED，不再误报已备份。共享去重的同一原件对所有成员一起删除，无法恢复；手机本地文件不会删除，再次新建备份任务可以重新上传。界面确认文字明确说明这些结果。

文件占用或清理失败会显示“继续清理”。删除已开始后不再允许恢复，解除占用后可重试；服务重启也会继续已确认的清理意图。不会把文件误移到回收站再当作永久删除成功，也不会在磁盘删除失败时只删数据库记录。

## 实现

- POST assets/{48位ID}/purge要求admin、confirm=DELETE及当前deleted_at；拒绝权限不足、未确认、活动文件和过期回收站记录。
- 数据库事务持久化assets.state=PURGING，asset_trash记录保留到文件清理完成；文件操作失败保留可重试记录。
- 只移除明确的原件和对应缓存文件，不递归删除。核对canonical边界、路径别名和其他asset对同一存储路径的引用。
- 缩略图线程与删除使用同一asset互斥量，后台查询跳过回收站。入库最终事务拒绝已开始彻底删除或已删除的asset，避免去重路径复活记录。
- 最后事务清理来源/图集/目录/回收站和asset记录，更新历史上传状态。启动恢复在正常上传和缩略图工作开始前幂等完成PURGING。
- Web确认对话框默认焦点为取消，输入内容完全匹配才可提交。失败后刷新记录，不把错误当成功。

## 验证

使用隔离Windows服务和合成文件，测试原件与缩略图实际消失、跨用户去重、拒绝活动文件和过期确认、路径越界、Windows文件占用后的继续清理、已删原件时重启收尾、重新上传，以及恢复/彻底删除并发只能有一个成功。回收站92项、原有smoke86项、文件夹22项回归通过；Node执行生产确认函数，验证取消/错误输入不发请求和正确提交携带指定记录。本次没有通过浏览器操作真实资料库，也不声称已完成浏览器端人工验收。

## 本轮Android CI错误

MediaPreviewActivity.onCreate直接调用声明throws Exception的settings.session()，缺少catch，导致javac拒绝编译。之前Java语法解析无法检查受检异常，这是本地检查范围不足。

现已捕获会话读取/解密异常，记脱敏诊断、提示重新登录并关闭播放页，不在无有效会话时初始化播放器。新增MediaPreviewActivityTest，以无效密文验证安全结束；完整Android类型检查、Lint、Robolectric和设备测试仍须新的CI。没有去掉受检异常声明，也没有跳过编译或测试。
