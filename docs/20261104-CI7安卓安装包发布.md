## 新部署

1. 完整解压，运行 `deploy/import_android.bat`，将随包 APK/r5 发布到本配置的数据目录。
2. 内网 HTTP 使用 `deploy/start_console_http.bat`；服务安装、启停和防火墙入口见 [deploy 说明](../deploy/README.md)。
3. 浏览器访问电脑地址，首页/登录页可下载随包安卓 App。
4. 全新数据目录首次登录使用 **admin / admin123**，登录后到“存储与设置”修改密码。

包内 `allow_external_hosts: true`；HTTP 默认端口仍为 8787，可修改配置或使用已有端口启动参数。该开关不自动改变监听模式、开放防火墙或配置外网穿透。所有运行路径按配置文件目录解析。

已有服务器更新前停止 NAS，保留原 config/data，再更新程序、web、deploy 和 client-release，执行导入后启动。保留原端口、数据路径等设置；如需允许外部 Host，在原配置显式修改。初始固定密码仅用于首次建立账号，不会覆盖已有密码。

## 手机升级与固定签名

CI7 与 CI5/CI3 的 Debug 证书不同，无法直接覆盖安装。旧手机先完成待上传任务；卸载会清除本机队列、登录与相册授权，电脑原件保留。诊断 ZIP 不是可恢复的队列备份。

后续源码已支持让 CI Debug 和 Release 使用同一份持久 JKS。需要仓库所有者一次配置四个 `ANDROID_KEYSTORE_*` / `ANDROID_KEY_*` Secrets，步骤见 [Android 签名说明](../android/README.md#签名与覆盖升级)。配置后以相同包名、签名和递增 versionCode 发布。未配置 Secrets 的构建仍是临时 Debug 签名，工作流会明确提示；PR 和隔离模拟器不使用私有签名。

CI7 Artifact 没有包含签名私钥，当前不能据此复原它的签名身份。切到固定 JKS 时，如果签名不同，仍需要处理一次换签；之后不要重新生成密钥。这项 CI 修改已递增下一次源码版本为 0.6.1-dev/code8，尚待后续运行验证；本次实际 APK 仍为 CI7 0.6.0-dev/code7。
