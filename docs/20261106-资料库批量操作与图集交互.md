# 资料库批量操作与图集交互

源码版本1.0.2，Android code18/nativeApi10，固定APK签名沿用。用户自行提交和推送，新的APK及完整部署包由CI产生。

## 使用

1. Web回收站：图片卡片显示缩略图，点击可放大查看。图片缓存缺失时可在权限检查后重新生成。原件下载和普通预览仍隐藏，未恢复前不能混入ZIP导出。
2. 点“选择文件”后全选本页或逐项勾选，可批量恢复；管理员可批量彻底删除。移入回收站有确认提示，永久删除必须输入“彻底删除”。不增加隐式清空回收站。
3. Web照片：时间线、文件夹或图集内支持跨页选择、移入回收站、移动和ZIP导出。批量移动选择来源与目标文件夹；所选文件必须属于来源文件夹，其他目录中的关联保留。
4. Web/APK图集：编辑/添加内容有明确的配色；添加照片时已有成员标记“已添加”，不能再次选中。“全选这一天”会翻阅当天完整分页，排除已经添加的内容。
5. APK开源页：卡片式入口、统一绿色主题、组件说明及许可全文的阅读样式；保留三份许可文件及完整条款。硬件返回键会返回上一页，不直接关闭应用。

## 数据量与一致性

选择上限1000项，写操作按100项分批，操作期间阻止重复提交。成功的分批从选择中移除，中途失败说明完成数并刷新数据，剩余项可重试；不承诺跨多个物理删除请求整体回滚。永久删除仍使用各自deleted_at防止过期操作，沿用PURGING持久化和恢复机制。手机本地文件不会被删除。

整天时间范围由当前设备本地午夜换算为毫秒区间，后续游标沿用相同筛选。服务返回from/to回执；图集查询返回membership_album_id与每项in_album。新客户端不接受旧服务忽略这些参数后的结果，避免把整个资料库误当作当天。成员查询仅检查当前页ID，不扫描整个图集成员列表到应用内存。

APK的整天辅助查询使用selectionOnly，不替换当前可见页的原生预览缓存，避免选择后续分页后返回首屏却无法打开照片。切换页面/账号或取消选择后，旧日期查询结果不会再进入选择集合。

ZIP导出通过原生浏览器表单下载，接口接受JSON或表单selection。身份校验后先核对选中原件，任一回收站/缺失项使导出在输出ZIP前失败。实现无压缩ZIP64，64KiB分段读取，CRC32和中央目录写入下载流，不写临时整包，也不把整段视频装进浏览器内存。文件名去除路径字符并加序号，保留可表示的修改时间。当前以小型真实文件验证ZIP64结构，未声称完成大于4GiB整包验收。

新增CMake轻量sync_web目标，解决只修改网页时增量编译没有更新运行目录的问题；不会因此重复复制整份FFmpeg。

CMake Release与直接VS工程Release均已构建通过；直接VS工程同步加入export.cpp/export.hpp。增量构建后核对运行目录与源码的共享控制器哈希一致。

## 验证

本机真实Windows服务：新增资料库测试71项（含55张合成照片入库），验证按天跨页、图集成员标记、授权回收站预览及缓存重建、ZIP CRC/重名/Unicode/字节/时间、表单下载、混入回收站拒绝及批量移动/恢复。原有回收站92项、基础smoke86项、图集13项、文件夹22项通过。

使用jsdom运行生产控制器，验证205项整天跨页选择、已有2项时只添加203项、超过100项分批提交、批量移动来源/目标、ZIP提交、永久删除文字确认及取消不发请求。测试依赖锁定于tests/dom/package-lock.json，Node22与DOM检查已接入Android和Windows打包CI，不进入生产APK或部署包。

23项Android主机回归、14项发布回归（含22项Node检查）及版本/协议/工作流/原生依赖检查通过。此环境浏览器控制入口启动失败，未将DOM检查称作真实浏览器视觉验收；本机没有Android SDK，Android完整编译、模拟器和手机视觉效果仍待新CI及真机复测。
