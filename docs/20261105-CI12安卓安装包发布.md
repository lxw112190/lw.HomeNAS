# CI12 安卓与完整部署包

本轮电脑服务 **0.4.0-dev**，默认APK **CI12 Release 0.7.0-dev / versionCode10 / nativeApi4**，签名界面资源 **r7 / minNative4**。包含图集管理、时间线/图集切换、输入框去聚焦外框、分层返回，以及此前的视频封面、备份队列和日志等功能。

## 使用与升级

1. 将整个Windows部署ZIP解压到可写目录；保留目录结构，路径按配置文件目录解析。
2. 全新部署：先运行 `deploy/import_android.bat` 导入默认APK和r7，再运行 `启动服务.cmd`；浏览器访问 `http://127.0.0.1:8787/`。登录页可下载安卓APK。
3. 初始账号 **admin / admin123**，登录后修改密码。包内 `allow_external_hosts` 和 `allow_insecure_lan` 均为true，默认HTTP8787、HTTPS9443。端口可在 `config/server.json` 修改；服务/防火墙批处理位于deploy。
4. 已有部署先停止前台程序或Windows服务，备份配置与data；更新程序、web、deploy、client-release及依赖，保留原有配置和data，运行导入脚本后启动。重新导入不重置已修改的账号密码，不删除原件或上传进度。不要整目录覆盖真实数据。
5. 默认分发Release APK；CI12 Debug和Release已经核验为同一固定签名。首次从CI9及更早临时签名切换时，不能直接覆盖不同签名旧APK。先完成需要保留的备份/队列处理，再决定换装；卸载会清掉手机本地队列、授权和应用内设置，电脑端原件保留。
6. 从本轮固定签名版开始，后续保持同一签名、同一包名和递增versionCode，支持正常覆盖升级。不再重新生成签名身份。
7. 新APK首次启动启用其内置新版页面，避免旧资源遮住图集功能。需要单独更新资源时，在设置检查更新并下载r7；后续发布更高revision。

本轮还修正导入脚本的协议上限，使 `minNative4` 资源可以随APK正常导入。没有在开发机安装Windows服务或修改防火墙。
