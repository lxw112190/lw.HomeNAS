# 1.3.0：时间线、资料库维护与手机连接

源码准备版本为 **1.3.0 / Android code23 / nativeApi14**，固定签名和包名不变。本机实现与验证不等于新APK、模拟器及完整部署包已通过CI；线上发布由用户提交后原有并行流水线决定。

## 照片时间线

- 排序与游标使用同一表达式：有效EXIF `taken` → 文件 `modified` → 入库 `created`。时间及游标仍返回十进制字符串。
- Windows WIC读取EXIF DateTimeOriginal和OffsetTimeOriginal。有效范围1970～2100；检查真实日历日期，拒绝无效日期滚动。无偏移时按服务器本地时区解释，不猜文件名。
- 新增持久化字段taken/taken_text/taken_zone/metadata_scanned及对应表达式索引。旧照片在独立后台线程逐张处理，重启继续；与预览/永久删除共用asset互斥。每张只标记处理一次，读不到EXIF时保留文件时间和原件。
- Web和APK共用 `timeline-tools.js`：年/月定位、包含结束当天的日期筛选、清除日期；改变范围属于新的选择上下文，旧分页/跨页勾选不能带入新范围。日历接口按调用方传入的当前UTC偏移汇总；日期范围由客户端本地日界线转换为毫秒，使用半开区间。
- 元数据仍按需展开；卡片日期与时间线一致。旧照片补索引期间可浏览，页面提示剩余数，处理结束后刷新。

## 资料库备份与迁移

### 网页一键快照

管理员在“存储与设置 → 资料库备份与迁移”创建并下载ZIP，使用SQLite Backup API获取一致性副本，不直接复制运行中的catalog.db/WAL。ZIP64流式下载固定的catalog.db、config/server.json和backup.json，包含账号及目录/主题图集/回收站关系。会话凭据与明文bootstrap密码从副本中排除，原库不变。

快照不含媒体原件或未完成上传文件，不能单靠它恢复已丢失照片。服务端保留快照副本，列表展示最近100份；请自行私下保管下载文件，勿放入公开Git仓库。未配置自动定时或异地备份。

### 整套换盘 / 换电脑

停服后运行 `NasServer.exe --migrate-to 空目录`。CLI取得与服务器相同的instance.lock，运行中拒绝迁移；路径不能包含/位于源程序、源数据目录内，不跟随重解析点，也不覆盖非空目标。

复制运行文件、web/config/deploy、原件、账号/分类、维护目录、未完成上传及已有缩略图。忽略日志、历史快照、instance.lock、源数据库WAL/SHM和初始密码便条。数据库单独做一致性副本，config改为可携带相对路径，登录会话清除。不会移动或删除源目录。

从复制开始即写入 `migration.json complete=false`；程序启动既检查EXE目录，也检查目标数据根，不能用旧EXE加--config绕过未完成标记。每个复制文件核对源/目标SHA256，写入files.jsonl清单并刷新；完成后再次检查全部文件、清单摘要、SQLite quick_check/foreign_key_check、READY原件对应的大小/摘要，以及未完成上传的确认偏移。通过后才原子标记complete=true。

`--verify-library 迁移目录` 用于首次启动前核对整份复制结果。迁移到新电脑时复制整个完成目录，在新电脑校验后启动；旧服务需卸载后再在新位置安装，手机更改地址并重新登录。TLS证书随整套资料保留；若新机地址不在旧证书SAN中，HTTPS需为新地址重新配置证书并在手机重新核对信任，不能忽略主机名校验。默认HTTP可用于首次连接。

校验清单描述迁移时刻，开始正常使用后数据库/配置/原件集合会变化，不拿旧清单反复校验活跃库。目标空间不足、链接或校验失败时保留未完成目标供排查，改用另一空目录重试，源目录始终保留。

### 从快照恢复分类

`--restore-backup 快照解压目录 --migrate-to 另一空目录` 使用快照的数据库/配置，原件来自当前源库，逐项对照快照检查，缺失或变化拒绝确认完成。恢复不覆盖当前库。

元数据快照中的未完成任务标为ERROR / RESTORED_METADATA_RESELECT、确认偏移清零，需要在客户端点重试，源授权失效时重新选择；不能把不在快照内的临时文件当作已确认备份。完整迁移则保留原确认进度，已验证复制后的4KiB确认偏移和后续实际续传字节。

## 文件夹主入口

Web/APK默认进入文件夹，保留一级逻辑目录设计，显示“资料库 / 当前位置”、文件数、照片/视频数和内容大小；大小是目录引用内容汇总，不等于去重后的磁盘新增占用。

批量移动沿用冻结ID、共同可写来源和每批100项的规则，APK新增固定folderMoveOptions桥接后也能移动。额外主题图集动作收进“更多整理”；进入“添加图集内容”时直接提供所需动作，并标记已加入的照片。旧图集及成员关系保留，没有自动合并、删除或复制原件。

目录明细的数量/容量采用一次聚合查询；仅做上传/写入权限核实时跳过汇总，避免每加入一张照片都重新扫描大目录。

## 手机连接

网页“连接手机”列出本机可访问地址，优先当前访问的非loopback地址，使用本地Nayuki QR Code generator v1.8.0生成SVG，不依赖外部二维码服务。二维码只包含服务器URL，接口需登录，不携带密码或token。

APK通过ZXing Embedded4.3.0扫码，使用时请求相机权限；不依赖Google Play服务。扫码结果只接受HTTP/HTTPS根地址，不接受用户信息、路径、参数或其他协议；仅填写连接草稿，既有Keystore端点AAD、认证会话、备份队列不变，仍需手动测试及登录。

成功测试或登录后保留最近5台服务器，去重并移动到最近。连接测试报告地址、DNS、TCP、超时、HTTPS证书或HTTP/服务识别阶段及耗时，继续沿用有界诊断日志，不记录密码或扫描原文。失败不会把旧队列转发给新服务器。

点击最近服务器会同步原生连接草稿并刷新界面状态，避免轮询把登录页地址改回上一次草稿；仍不修改已认证端点、密文或队列归属。
