# 完整部署包：启动即可下载 APK

日期：2026-11-12。

客户只需下载完整 Windows ZIP，完整解压，运行 `NasServer.exe`（或根目录的启动命令），也可以管理员身份运行 `deploy/install-service.bat` 安装并自动启动。手机访问服务网页，在登录页点下载安卓App，无需预先登录或执行导入命令。服务安装和防火墙仍使用现有七个BAT。

```text
lw.HomeNAS/
  NasServer.exe
  config/
  web/
  deploy/
  client-release/
    apk.json
    <SHA256>.apk
    verification.json
    ui.json             可选
    <SHA256>.zip         可选签名页面资源
```

原CI已将同提交、固定签名且核验通过的APK和清单装入client-release；本次去掉客户手动导入这一环节。该目录以EXE位置为基准查找，前台和Windows服务共用启动路径，不依赖工作目录。裸后台开发包可以没有APK，不影响文件备份功能。

## 自动发布规则

- 按apk.json/ui.json定位固定SHA256文件，不遍历其他磁盘，不按文件名或修改时间猜最新版本。
- 校验清单、文件大小、SHA256、版本号及UI原生协议要求；APK最多128MiB，资源最多20MiB。源文件不能通过文件链接越过client-release目录。
- 校验成功后复制到配置的数据目录maintenance/packages，复制后再次核对，原子替换发布清单。相同版本、相同内容不重写目录，保留管理员已有说明；文件仍校验完整性，不只是相信文件名。无需客户电脑安装Python/Java/Android SDK。
- 已发布更高versionCode/revision时保留较新版本；同版本不同内容拒绝自动覆盖。错误、文件缺失、半复制或校验失败写控制台/服务日志，NAS正常启动，保留原有已发布版本。APK和可选UI独立处理。
- 管理员撤下时保存撤下版本水位。重启不重新发布同版或更旧版本；严格更新的版本可以自动发布。撤下意图先持久化，即使清单删除中断，公共目录也隐藏该旧版。
- Web管理员显式发布会清除相应撤下标记；旧deploy/import_android.ps1作为停止服务后的显式重新导入入口保留，也清除标记。不要把维护标记手工删除作为日常升级步骤。
- CI继续验证APK固定证书及内容签名。后台启动校验文件清单/摘要，不把verification.json文本视为运行时签名验证；APK内的签名页面资源验证继续由原生客户端执行。

升级时停止服务，保留config/data，替换新程序、web和整个client-release后启动即可。手机仍通过系统安装或覆盖升级APK；服务不会代替用户在手机上确认安装。

- Windows Release编译和新增隔离启动回归通过：空目录、首次发布、匿名下载、重复启动、保留说明、升级、防降级、同版冲突、坏清单/文件/缺失、撤下持久化与中断意图、手动发布、UI协议和临时文件清理。
- 现有维护接口与86项smoke通过，24项发布工具回归及版本/协议一致性检查通过。
- 用本地已有的固定签名CI18 Release APK核对真实证书、完整哈希，验证新后台自动发布后匿名下载字节一致；该旧APK仅用于文件传输验收，不声称它是本次构建的新APK，也未安装到手机。
- 完整ZIP验收脚本已改为首次直接启动，禁止提前导入，再检查公共APK/可选UI下载。新完整ZIP、同提交APK及云端流水线仍需本次推送后由CI生成并验收；没有本地安装Windows服务或变更防火墙。

本次不修改APK生产代码、版本号或签名，不自动提交/推送/发布。源代码版本仍为1.1.1，是否正式升版发布另行决定。测试只使用隔离目录，不接触真实资料库。
