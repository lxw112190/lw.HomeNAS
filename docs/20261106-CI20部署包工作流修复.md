# CI20有APK但没有完整部署包

来源提交：8d42655d3186cd951a495b834d7f30523f24e269，版本1.0.0 / APK code14。

实际云端状态：

- [Android CI20](https://github.com/lxw112190/lw.HomeNAS/actions/runs/42127757104)：apk与emulator任务均成功。APK Artifact为lw.HomeNAS-Android-20。
- [release.yml失败运行](https://github.com/lxw112190/lw.HomeNAS/actions/runs/42127754931)：配置阶段失败，任务列表为空，没有开始Windows编译、验收或上传部署包。

上次调整checkout时使用了过宽的文本替换，错误地在select任务中加入needs.select.outputs.sha，并在package任务中重复写入ref键。普通PyYAML SafeLoader会静默覆盖重复键，之前的测试没有检查任务依赖，导致本机测试通过但GitHub拒绝工作流。

修复：select检出当前可信工作流来源，不引用自己的未来输出；package和publish各保留一次所选SHA的ref，继续保证Windows与APK使用相同提交。没有移除模拟器门槛或改动版本发布规则。

新增tools/check-workflows.py：拒绝所有层级的重复YAML键、未声明的needs引用、自依赖、缺失任务和依赖环。对4份工作流执行，并回归重复checkout ref、自引用及依赖环。Android前置步骤显式安装Python3.12和PyYAML，在构建APK前检查工作流；Windows发布入口也检查。此检查范围有限，不能代替GitHub完整Actions校验及执行。

本机14项发布回归（含22项Node检查）、20项Android主机回归和git diff --check通过。修改仅涉及CI、校验工具和文档，保持1.0.0/code14及固定签名。推送后运行新的CI才会使用修复；旧失败运行不包含本次修正。新完整ZIP及正式Release状态仍以新CI为准。
