# APK音视频播放修复（1.0.1 / code16 / nativeApi9）

## 诊断依据

用户提供的两份原件仅在本机只读分析，没有修改原件、写入真实资料库或纳入Git。MP3为48kHz双声道320kbps，约1.29秒；MP4为约5.68秒、1080p HEVC Main（hvc1）与AAC-LC。MP4不是H.264；桌面浏览器的可播放结果不能说明Android WebView一定支持相同解码路径。

三处代码问题：

1. APK预览只创建img/video，没有audio分支；旧资料库的MP3类别为file，不能只按category=audio判断。
2. 视频全部依赖WebView解码，错误码4既可能是读取失败，也可能是WebView的格式支持限制，旧提示归因过于绝对。
3. assetMetadata桥已调用metadata接口，但NativeApi路径白名单漏掉metadata，尚未联网就抛出“不支持的接口”。

## 修改

- 保持单屏预览布局。打开音视频后点“播放视频/播放音频”，进入应用内Media3原生播放器；可暂停、拖动进度和返回。图片预览继续使用现有缩放功能，文件信息仍在原预览页按需展开。
- 使用AndroidX Media3 ExoPlayer/UI 1.5.1，兼容当前compileSdk35，启用设备解码器回退和有界缓冲；不是捆绑FFmpeg软件解码器，不承诺所有手机或所有编码均可播放。[官方组件说明](https://developer.android.com/media/media3/exoplayer)、[固定版本源码](https://github.com/androidx/media/tree/1.5.1)。
- MediaPreviewActivity不导出，只接收资料库ID、大小、MIME和会话revision。NasMediaDataSource将原生播放器读取映射为精确Range请求，复用NativeApi认证、HTTP开关、自签名证书及主机名检查；不通过JS传递服务器地址或令牌，不开放任意URL。
- 精确核对206/Content-Range，拒绝错误返回，不先下载整段视频；关闭/后台/旋转释放播放器，恢复前台时恢复位置，读取时检测会话变化。音频焦点和拔耳机暂停交给播放器处理。
- 修复metadata固定路由，并为旧客户端回退路径补audio MIME支持；未支持格式不再永久显示“正在加载”。
- 协议升到9，资源包构建、服务接收及导入边界同步；旧已下载界面首次升级时回到新内置页面，防止旧WebView播放页遮住新功能。ClientMaintenanceTest以旧协议8验证迁移，保留同协议资源回退断言。固定APK签名沿用。

## 验证范围

- 本机Windows Release构建、86项基础smoke、15项媒体检查通过，媒体检查新增完整区间和seek区间的精确206/字节比对。
- 21项Android主机回归（含执行生产预览逻辑的Node测试）、14项发布回归（含22项Node检查）、版本/协议一致性检查通过；36个Java文件语法检查通过。
- 新增Robolectric测试：metadata认证路径、旧file类别MP3、原生Range读取/跳转、退出登录、任意URI和错误206拒绝。
- 新增模拟器NativePlaybackTest，用生成的2秒440Hz正弦MP3经过认证Range源，由真实ExoPlayer解析并检查READY、时长和跳转。测试音频位于androidTest/assets，不是用户录音，不进入正式APK资源。
- Android依赖解析、Lint、完整编译、Robolectric及模拟器仍待新CI；用户提供的HEVC和MP3在真机上的实际播放尚未验证。

## 真机复测

1. 安装新的固定签名code16 APK，使用现有用户名密码登录；已有录音和视频无需重新上传。
2. 打开MP3，点“播放音频”，确认时长、播放/暂停和进度可拖动；返回后声音停止。
3. 打开HEVC视频，点“播放视频”，检查画面、声音、拖动进度、旋转以及退出后停止播放。
4. 展开文件与拍摄信息，确认不再出现“不支持的接口”；没有EXIF时只说明原件未提供。
5. 若仍失败，从APK导出诊断包。新增player.start/player.open/player.error包含媒体MIME、状态、偏移和错误码，不记录媒体名称、令牌或原件内容。

1.0.0已公开发布，不覆盖旧附件；提交后由现有CI构建1.0.1/code16，再验收新的完整部署包。
