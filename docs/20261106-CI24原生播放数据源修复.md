# CI24原生播放数据源修复

源码版本1.0.1，APK由code16递增至code17，原生协议9及固定签名保持。新的Android编译、Robolectric及模拟器结果须由后续CI确认。

## 实际失败

[Android CI24](https://github.com/lxw112190/lw.HomeNAS/actions/runs/42164991524)对应提交6cb8aea01cef8f24eb39bd665d5b8f595a5dc041。apk任务成功，emulator任务失败，设备8项测试中1项失败。正式发布工作流因此跳过，没有放行不完整版本。

失败用例为NativePlaybackTest.realMp3DecodesAndSeeksThroughAuthenticatedRangeSource，断言期待Player.STATE_READY（3），实际为STATE_IDLE（1）。下载的Android-emulator-reports-24中，单用例logcat给出ExoPlaybackException: Source error，其cause来自NasMediaDataSource.open抛出的IOException（无效播放请求）。最后的dumpsys和run-as只是诊断阶段输出，并非首个失败原因。

[Media3 1.5.1的ProgressiveMediaPeriod源码](https://github.com/androidx/media/blob/1.5.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/source/ProgressiveMediaPeriod.java)在buildDataSpec中为普通渐进式媒体也设置ICY_METADATA_HEADERS，具体为Icy-MetaData: 1。旧数据源的非空httpRequestHeaders检查在真正发起网络读取前拒绝了该请求。之前的手写DataSpec夹具未设置这个默认头，所以基础数据源用例没有发现此问题。

## 修改

- 仅接受Icy-MetaData（大小写不敏感）且值为1的本地提示，不转发给NAS，不改变静态文件字节流。
- 保留固定资料库URI、GET、无正文及会话检查；Authorization和Range仍由NativeApi自行生成。其他调用方请求头继续拒绝。
- 原生数据源JUnit夹具加入真实默认头，检查仍使用原认证和正确Range，并断言Icy提示未转发；补Authorization/Cookie/Range/Host及错误Icy值的拒绝用例。
- 真实ExoPlayer模拟器用例保留READY、时长、跳转断言，增加onPlayerError捕获。一旦播放失败立即携带errorCode及cause抛出，不再只等待20秒再显示状态差异。
- CI日志补充播放器错误标签；dumpsys完整输出保留附件，控制台末尾从JUnit提取失败用例及堆栈，同时保留原始退出码。可选日志收集及摘要失败不覆盖真实测试失败。

## 本机验证范围

22项Android主机回归、14项发布回归（含22项Node检查）、版本/协议及工作流检查通过。以下载的真实CI24 JUnit XML验证摘要提取；主机用例模拟测试失败且应用日志已卸载的情况，仍返回原始失败码和NativePlaybackTest摘要。

没有本机Android SDK，不把这些检查称作APK重新编译、真实解码或真机通过。没有跳过失败测试、放宽READY断言或修改固定签名。CI报告保存在忽略的test-results目录，不随源码提交。
