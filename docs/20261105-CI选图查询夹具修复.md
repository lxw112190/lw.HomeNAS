# CI 选图查询夹具修复

失败用例：`MediaPickerQueryTest.wholeDayExceptOneDoesNotEnqueueTheExcludedPhoto`，原第66行为`picker.enqueue(...)`，32个JVM用例中1个失败。

## 原因

入队前的真实调用链是：

```text
MediaPicker.enqueue
  → MediaCatalog.describe
  → ContentResolver.query(uri, null, null, null, null)
  → 测试Provider的传统五参数query重载
```

测试Provider为检查“列表必须显式使用Bundle和SQL排序”，将传统query重载直接设为AssertionError。但是单项文件的大小/修改时间读取合法地使用这个重载。此前只在Bundle重载内补了projection为空的返回，未覆盖实际触发的五参数重载，导致用例尚未执行队列内容断言就失败。

这是测试夹具的重载覆盖遗漏；本轮不修改排除算法、上传队列或生产媒体读取代码。

## 修改

- 根据`/images/media/{id}`和`/video/media/{id}`识别单项URI。
- 单项元数据由同一方法处理，两种query重载都支持空projection和指定projection，返回对应ID的名称、大小、修改时间及volume_name。
- 集合的传统query仍抛出AssertionError，保留原来的列表排序约束。
- 原用例仍必须确认只入队1项，且URI为未排除的照片；未跳过或放宽断言。
- 新增通过真实ContentResolver读取单项元数据的用例，以及明确拒绝集合传统查询的用例。

本机`tools/check-android.py`和20项Android主机检查通过；Java语法检查通过。本机没有Android SDK，完整Robolectric/JVM执行需提交后在CI复验，不标为32项已通过。

本轮仅修改测试源码和记录，APK生产源码保持0.8.0-dev/code13；上一轮CI失败未产出新分发APK。保持现有签名及全部构建、Lint、测试门禁。
