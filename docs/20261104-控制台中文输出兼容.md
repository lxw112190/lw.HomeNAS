# Windows旧控制台中文输出兼容

版本0.2.3-dev。用户在Windows Server 2012 R2的CMD中直接启动时，中文横幅显示为UTF-8字节被错误解释的字符。旧程序使用窄字符std::cout输出UTF-8，并强制修改当前控制台输入/输出代码页；这不能覆盖旧控制台的字体、宿主和中间管道差异。

## 实现

新增统一consoleText输出入口。对真正的控制台句柄，用GetConsoleMode识别，再把完整UTF-8消息转换为UTF-16，通过WriteConsoleW输出；处理CRLF及分块边界的代理对。取消程序启动时的SetConsoleCP/SetConsoleOutputCP，不再改变调用者的代码页。

stdout/stderr被重定向到文件或管道时，保留UTF-8字节。Windows服务把iostream切换到service.log的情况下，也继续写入该日志，不尝试向控制台输出。服务横幅仍不打印初始化密码。

统一覆盖启动信息、中文数据目录、启动错误、设置密码提示及版本/摘要输出。PowerShell的Console和AdminPassword入口使用Start-Process -NoNewWindow让子程序继承控制台，避免PowerShell 5.1对原生输出的二次解码；保留程序退出代码。源码Run.cmd和打包生成的启动服务.cmd取消强制chcp，脚本内容保持ASCII。

微软文档说明：[WriteConsole](https://learn.microsoft.com/en-us/windows/console/writeconsole)支持Unicode形式的WriteConsoleW，但重定向句柄需另行写文件；可用GetConsoleMode区分。[SetConsoleOutputCP](https://learn.microsoft.com/en-us/windows/console/setconsoleoutputcp)也说明代码页设置受控制台字体行为影响。

## 使用

停止旧程序，用新版NasServer.exe替换原EXE，保留原config和data。重新打开CMD，进入程序目录，继续用原来的命令：

```bat
NasServer.exe --allow-insecure-lan
```

8080端口及allow_external_hosts沿用现有配置，无需为本轮修复调整。如果使用start_console或set_admin_password批处理，同时更新deploy目录中的脚本。

## 验证范围

本机Windows 10上，以独立隐藏控制台创建真实屏幕缓冲区，通过ReadConsoleOutputCharacterW读回字符，分别检查437、936、65001代码页下的中文错误以及调用者代码页保持不变；检查真实服务启动横幅、中文目录、改密提示不回显密码、PowerShell 5.1两种入口的Unicode错误和退出码、文件/管道严格UTF-8解码，共14项。

测试命令：`python tests/console_encoding.py`。测试使用一次性目录和自己的进程，不更改用户控制台、不安装服务。另行运行账号/备份73项及离线改密/HTTP日志13项回归。

没有Windows Server 2012 R2虚拟机或实机验收，本轮只能确认采用旧系统已有的Unicode API并在本机通过上述检查。用户目标机的实际字体显示和完整系统兼容性仍需验证，不能据此宣称整个项目的最低系统版本已调整。
