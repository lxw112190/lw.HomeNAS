# 自动打包与发布

新增工作流 **Full package and GitHub Release**：`.github/workflows/release.yml`。

## 默认流程

推送 main 中的程序、Web、Android、配置、部署脚本、构建工具或发布流程修改后：

1. 原有 **Android APK** CI 运行，复用现有四个签名 Secrets，完成构建、Lint、JVM单测和Android15模拟器检查。
2. Android工作流全部成功后，自动触发完整包工作流。验证该任务来自本仓库main、受支持事件且APK和模拟器两个job均成功；选择它同一次构建的APK，不取其他提交的“最新包”。
3. Windows2022 runner检出同一提交，核验APK实际v2签名、整包内容摘要、固定证书、版本、内置页面、资源公钥及编译提交；依据固定哈希恢复FFmpeg及其源码/许可，构建Windows Release。
4. 运行84项冒烟、图集、时间线、服务/防火墙计划及实际完整ZIP验收。测试仅启动隔离NAS，不在runner安装Windows服务或修改防火墙。
5. 上传完整包Artifact，再创建GitHub Release草稿；5个附件均上传成功后公开为 **预发布版**。当前服务和APK均带dev标识，因此不自动标成正式版。

发布标签采用 `ci-Android运行序号`，例如Android CI13对应`ci-13`；它与新工作流自身的运行序号不同。完整包文件例如 `lw.HomeNAS-0.4.0-dev-ci13-win-x64.zip`。

附件为：完整Windows ZIP、ZIP的SHA256、独立Release APK、APK的SHA256、`release-manifest.json`。Manifest记录服务/APK版本、APK版本号、Android CI号、提交、包哈希和界面来源。包里包含Web、默认APK、部署批处理、FFmpeg和许可，不包含真实data、日志或私钥。

GitHub Releases入口：[lw.HomeNAS/releases](https://github.com/lxw112190/lw.HomeNAS/releases)。默认账号仍为admin/admin123（首次创建后修改）；`allow_insecure_lan=true`、`allow_external_hosts=true`，已有账号密码及原件保持。

## 首次启用

无需新增APK签名密钥或PAT：已配置的Android签名Secrets继续使用，GitHub自动令牌仅在最终publish job取得contents写权限。构建和源产物选择job保持只读。

把本轮修改提交到main即可开始第一轮。新增工作流必须先存在于默认分支，才能收到后续 `workflow_run` 事件；[GitHub官方事件说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run)。不要把尚未包含本轮发布脚本的历史CI12当成首个自动发布来源；首次推送后生成的新Android运行才包含完整发布工具。

## 手动触发

Actions → **Full package and GitHub Release** → **Run workflow**：

- `android_run_id`：填写Android工作流URL中的数字ID，例如 `/actions/runs/41948167962` 中的数字，而非显示的CI12序号。留空选择最近的合格main构建。
- `publish`：默认true，自动发布预发布版；取消勾选则仅生成已验证Artifact，不写GitHub Release。

Android源工作流必须启用模拟器并通过；过期/缺失/不属于同一提交的APK Artifact不能用来新建发布。获取其他运行的Artifact使用同仓库只读令牌，[官方下载Action说明](https://github.com/actions/download-artifact)。已公开的同提交Release重跑会跳过，不覆盖已下载版本；其旧APK Artifact过期也不影响跳过。

发布中断时只留下草稿。重跑可恢复同提交草稿；不允许覆盖其他提交的标签，不会公开带额外未知附件的草稿。若需更改软件内容，生成新的Android构建和发布标签。

## 可选：独立签名界面资源

**不配置新的Secret也可以自动发布完整软件。** APK内已含完整界面；此时包里不放`ui.json`，客户端直接使用内置页面。

若希望每个自动包也附带可单独更新的签名界面，将现有资源私钥配置为 `UI_SIGNING_KEY_BASE64`。必须使用当前 `ResourceTrust.java` 公钥对应的原有私钥，不能重新生成。可在项目目录手动执行下列PowerShell，将Base64直接交给GitHub CLI，不打印密钥：

```powershell
$uiKeyBytes = [IO.File]::ReadAllBytes((Resolve-Path '.\local-signing\resources-private.pem'))
[Convert]::ToBase64String($uiKeyBytes) | gh secret set UI_SIGNING_KEY_BASE64 --repo lxw112190/lw.HomeNAS
```

需要已安装GitHub CLI并登录。私钥只在runner临时目录解码，结束后清理，不进源码、Artifact或部署ZIP；签名公钥不匹配时发布失败。

自动界面revision使用保留区间 `1000000 + Android CI运行序号`（CI13生成r1000013），minNative当前为4。历史手工r7保留；自动资源启用后应继续采用递增自动revision，不回发低版本资源。APK修改仍需维护`versionCode`和`versionName`，流程不生成版本提交、不更换签名。

## 本机验证与边界

使用收到的真实CI12 APK，已本地执行新的完整打包入口：Windows Release、84项冒烟、13项图集、9项时间线、服务/防火墙计划、实际ZIP17项验收全部通过。另验证“不配置资源私钥”分支的完整包，17项验收通过。签名资源和APK内置界面两种包均可导入、下载、生成视频封面和操作图集，重启/重新导入保留修改过的密码。

18项Android主机检查、5项Python发布检查、20项Node发布选择/草稿/附件检查通过。Node发布测试用假API，未创建真实标签、草稿或公开Release。还验证了实际5个附件的文件名和哈希。首次远端Windows runner到GitHub Release的链路仍需本轮推送后验证，不能把本地模拟API称为已在GitHub发布成功。

本轮只改构建、校验、发布和文档，不改APK应用代码，待发布APK仍为0.7.0-dev/code10。用户已反馈CI12版本“都测了，没有问题”；未来新构建仍不自动宣称完成真机验证。
