# CI 选图测试队列隔离修复

第二轮CI共34项JVM测试，其中两项失败：

- `changingDestinationInvalidatesAnOldSelection` 原第99行。
- `expiredExclusionRejectsBeforeAnyEnqueue` 原第93行。

两行均是断言当前账号队列数量为0。此前的`assertThrows(IOException.class, ...)`已经通过，说明过期排除和目标变化均被拒绝，失败发生在随后统计队列时。

第一轮修复单项元数据查询重载后，`wholeDayExceptOneDoesNotEnqueueTheExcludedPhoto`能够成功入队1项。但这组用例共用`fixture-server:picker-test`，原@Before没有重置TaskStore单例或数据库。生产单例持有旧Context和SQLiteOpenHelper，仅靠Robolectric重新创建Application不足以隔离它，成功用例的记录影响了之后两个“不得入队”的统计。

本轮增加仅位于`src/test`的QueueFixture，在TaskStore类锁内关闭旧helper、清空静态instance，再通过Context删除测试队列数据库。MediaPickerQueryTest和TaskStoreTest均在@Before/@After调用；选图夹具显式清理并初始化设置偏好，在@Before增加空库断言，测试结束清理媒体句柄。

原来的零条断言、排除后恰好1条且URI正确的断言、异常检查及顺序检查全部保留。没有指定方法执行顺序，没有跳过测试，也没有修改APK生产代码或真实资料库清理逻辑。TransferProgressTest已按独立scope在finally清理其数据，检查后保持原样。

本机Android源布局检查及20项主机回归通过，32个Java文件语法检查通过。完整34项JUnit及Android构建仍需在CI复验。本轮仍是测试修复，失败版本尚未分发，APK维持0.8.0-dev/code13，签名不变。
