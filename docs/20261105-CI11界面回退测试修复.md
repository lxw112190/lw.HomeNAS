# CI11 界面回退测试修复

失败记录：[Android APK / run11](https://github.com/lxw112190/lw.HomeNAS/actions/runs/41947154775)，提交 `4083afe650e517c1ed0959913d95efffe7786f67`。实际失败用例是 `ClientMaintenanceTest.failedUiLaunchReturnsToPreviousVersion`，在第15行出现 `NullPointerException`；20个测试中1个失败。签名恢复步骤成功，失败发生在JVM测试步骤，尚未发布本轮APK。

原因：nativeApi4 增加首次启动迁移逻辑，清除旧活动/待启用资源指针并启用新APK内置页面，因此 `beginLaunch()` 正确返回 `null`。旧测试直接预置活动资源，没有模拟首次迁移完成，就对返回值调用 `getName()`。此前修改升级逻辑时遗漏了这个测试前提。

修复保留生产升级行为和失败回退能力：先模拟当前APK首次启动，再预置兼容的r7/r8测试资源，继续断言失败后回到上一资源版本。另增加旧协议升级清理资源指针并保留其他状态、已确认资源在下次启动继续保留、活动资源文件缺失时回退内置页面三项测试。没有跳过或屏蔽失败断言。

CI 新增 `tools/android-test-summary.py`，在 Gradle 步骤后始终打印已有 JUnit XML 中的失败用例和有限堆栈，完整报告仍上传 `Android-build-reports`；不覆盖 Gradle 退出状态。保留上一轮固定签名改动，供本次一并提交。

本机验证：Android资源/源码布局通过；18项主机检查通过；31个Java文件语法解析通过；工作流YAML及失败摘要的合成XML检查通过。**未在本机执行Android Gradle、Robolectric或模拟器测试，修复后的Android单测仍需CI复验。**

本次仅修改测试、CI及文档，没有修改APK应用代码，保留待发布版本 `0.7.0-dev / code10`。该版本上次构建失败，未作为新APK交付。后续实际修改APK仍递增版本并复用用户已配置的固定签名。
