# 家庭 NAS 系统详细设计（整体设计，0.2账号方案）

日期：2026-11-04。本文为整体设计，功能状态以 [lw.HomeNAS 当前说明](../README.md)为准：已开始实现电脑服务与网页前台备份，尚未实现 Android 自动备份或通过真机验证。

当前实现已升级0.2：统一用户名/密码登录，admin/member/viewer三角色，家庭资料库共享；旧配对接口已移除。原生Windows服务及deploy批处理已提供，实际安装启停尚需目标机验证。本文同时保留尚未实现的Android自动备份等整体规划，当前接口以[lw.HomeNAS API](API.md)为准。

Android客户端源码与CI已新增（0.3.0-dev），原生队列、相册和后台任务代码已编写；尚未执行CI或真机验证。见[客户端说明](../android/README.md)；本机不安装Android SDK。

## 1. 已确认的方向

- C++17、cpp-httplib、Windows x64 电脑服务器，通过 Web 页面管理。
- Android APK 沿用 lw.Web2Android 的网页打包、签名与升级体系，扩展专用 NAS Runtime。
- 首版只做家庭局域网；外网访问后续增加。
- 支持多部手机，默认单向备份，手机删除不联动删除服务器文件。
- 默认路径相对 exe/config 的固定基准目录解析，不依赖启动进程的当前工作目录；允许显式指定数据盘。
- PC 上不依赖浏览器窗口维持服务；手机自动备份不依赖 WebView 页面维持任务。
- 用户已经创建 [lxw112190/lw.HomeNAS](https://github.com/lxw112190/lw.HomeNAS) 远程仓库，本地独立仓库已初始化为main并配置origin。用户自行提交和推送，助手仅提供命令。
- **功能优先。** 首版按实际使用闭环推进，不因开源目标增加跨平台、通用插件框架、复杂 CI 或提前完整化文档。顺手隔离真实照片、数据库、设备凭据和 APK 签名密钥，固定实际依赖并保留许可说明；其余公开发布整理放在功能可用后。

首版目标是一套可恢复、可校验的家庭媒体备份系统。完整 NAS 的磁盘池、RAID、SMB、应用商店等另行设计。

## 2. 组件与边界

| 组件 | 职责 |
| --- | --- |
| NasServer.exe | HTTP/TLS 接口、认证、媒体文件接收与读取、任务调度、数据库访问；提供 console/service 两种运行模式 |
| Web 静态资源 | 一套响应式页面，电脑侧管理、手机侧相册浏览和任务操作；全部 JS/CSS/字体随包分发，不依赖外部 CDN |
| SQLite | 家庭成员、设备、媒体记录、来源映射、上传会话、后台作业和审计事件 |
| Android NAS Runtime | 媒体权限、扫描、持久化任务、摘要、上传、后台调度、凭据保存、受限网页通信与媒体读取 |
| Preview Worker | 图片缩略图、元数据提取、视频封面；失败独立重试，不阻塞原始文件入库 |
| FFmpeg/ffprobe（可选） | 视频元数据、封面及按需兼容预览；固定版本，作为外部工作进程，限定线程/并发/时间 |

cpp-httplib 采用阻塞 I/O，需配置线程池和等待队列上限。上传流式写盘，控制请求与媒体请求保留处理能力。首版可用独立的控制/传输监听器或分别限制上传槽位；槽位满时快速返回429，不把大量等待上传的请求长期阻塞在线程池里。

同一数据根目录只允许一个服务实例写入，console/service 启动都要取得实例锁，避免两个进程同时处理同一 `.part`。服务安装属于可选运行方式，安装时明确服务账号对配置、证书和数据目录的访问权限。

## 3. 用户使用流程

1. 电脑首次运行生成admin账号和随机初始密码，登录后修改密码；配置数据目录并检查剩余空间与可写性。
2. 管理员创建普通或只读账号；手机输入服务器地址，核对服务器身份后以用户名和密码登录。
3. 手机授予照片/视频访问权限，选择相册；显示实际可访问范围与预计文件数/大小。
4. 首次历史备份由用户点击启动，显示系统通知与应用内进度，可暂停。
5. 后续按网络/电量条件增量备份；服务器未启动时显示“等待电脑上线”，定时退避重试。
6. 手机或电脑按时间浏览，选择查看原图、播放视频、下载原文件；媒体预览尚未生成时可显示占位和状态。

建议首版手机产品最低 Android 10，保留 Runtime 原有较低 minSdk 的可能性，但旧系统不直接承诺全功能。最终最低版本待目标手机清单与兼容测试确定。

## 4. 网页与原生通信

推荐自动备份版采用 APK 内置页面，首次启动输入服务器地址或扫码。服务器不可达仍能显示本地排队任务及设置。电脑浏览器与手机复用页面组件，通过两种 Transport 适配器访问业务：BrowserHttpTransport、AndroidNativeTransport。

原生只开放连接登录、查询授权范围、选择相册、创建/暂停备份、读取任务摘要等固定命令。校验页面来源、主框架、命令 schema 和参数上限；不开放任意路径读取、任意 URL 请求或代码执行。APK 扫码要增加原生扫码能力，图片选择器本身不等于已经具备扫码器。

大视频由原生 ContentResolver 流式读取并上传；网页收到分页媒体信息和进度，不接收整份文件或大段 base64。缩略图与视频使用受限的流式媒体读取入口；视频必须传递 Range/取消信息，校验 206/416、Content-Range 与大文件拖动播放。该能力需要实际实现，不能仅把 access token 放进 URL。

现有 lw.Web2Android 无通用 Native Bridge，没有媒体扫描与上传 Service。扩展时采用独立 NAS Runtime profile，保持普通网页封装的默认行为。Worker/Service、权限、资源与依赖必须进入 Packer 生成的最终 APK；同时更新 Runtime 版本、schema、DEX 摘要和整包验证。单改构建用 Manifest 或替换 classes.dex 不足以完成集成。

## 5. 局域网连接与账号

- 手机可手工填地址；二维码为便利入口，mDNS 发现作为后续增强。IP 变化后按服务器身份重新定位，不能因主机名相同就信任。
- 建议电脑本机管理 HTTP 监听 127.0.0.1；手机数据服务使用 HTTPS。手机 Runtime 扫码确认并固定服务器公钥身份；证书错误不能用 WebView 全局忽略解决。
- 若手机网页直接从远程 HTTPS 加载，证书必须受 WebView 信任；原生 HTTP 客户端的公钥固定不会自动解决 WebView 证书问题。首版内置页面可减少这部分耦合。
- 如以后提供二维码，仅用于服务器地址与身份发现；不包含账号密码，不作为登录凭证。当前没有配对码入口。
- 账号登录后获得随机会话，服务端保存验证摘要；禁用账号、改密或调整角色撤销该账号旧会话。Android令牌存储拟用Keystore支持的加密方案，尚未实现。
- 接口按角色授权，本机访问不自动视为管理员；admin管理账号及全部任务，member管理自己的上传，viewer仅浏览下载。目前资料库共享，后续个人文件隔离另行设计。

HTTPS、会话撤销及本机管理口属于当前版本；公钥轮换属于后续设计；HTTP 可作为显式开发模式，不把局域网等同于加密传输。

## 6. 媒体扫描与身份

Android 使用 MediaStore/ContentResolver，保存媒体卷标识、媒体 ID、大小、修改信息、来源相册和 content URI 等本地记录；URI 和 ID 是定位信息，不是永久内容身份。使用变化标记并定期做完整核对，不能只按拍摄日期查新增，否则导入旧照片可能漏掉。

排除尚未写完、pending、零字节媒体。读取前后核对可观测版本与大小；扫描/摘要期间源文件变化则重新排队，不以旧摘要提交。权限缩小、媒体卷变化或数据库重建时重新扫描并用内容摘要与服务器对账。

Android 14 起用户可能只授权部分照片；页面必须明确“仅已授权媒体”，不能在此情况下显示“整个相册已全部备份”。已进入图库的聊天图片可以在授权范围内备份；其他应用私有目录不保证可访问。

服务器原件不可变。同一来源媒体被编辑后作为新内容记录，与旧版本关联。相册是来源或展示关系，不直接决定删除原件。

## 7. 上传协议：单文件顺序分块，多文件有限并发

建议起始参数：块大小 8 MiB，低配可降至 4 MiB；每手机同时上传 2 个文件，每文件同时 1 块，全局最多 4 个活跃上传请求。均为待实测默认值，不代表已达到的吞吐。

### 7.1 会话与流程

1. 手机计算完整 SHA256、大小和来源元数据，创建会话；创建请求带客户端任务 ID，重复提交返回同一任务结果。
2. 服务端在同一成员库内检查摘要与大小：已存在且原件可用时只添加来源关系；否则预留容量并生成 upload_id。
3. 手机查询会话，取得服务器确认的 offset 和 chunk_size。
4. 上传块，明确 offset、长度与块 SHA256。服务端检查权限、会话状态、大小及当前偏移后流式写入 `.part`。
5. 块完整且摘要正确，刷新文件持久化，再提交 SQLite 中的 confirmed_offset，最后 ACK。
6. 断网/重试先查询 offset；重复旧块返回明确的已确认状态或 409 与当前 offset，不能再次追加。单会话互斥，避免两个 Worker 同时写。
7. complete 时验证总大小与完整 SHA256，进入提交过程；complete 重试可查询到同一 asset_id。

SHA256 用于内容校验与精确去重，不代替设备认证。快速扫描指纹只用于减少本地重复扫描，不据此跳过完整文件校验。首版去重限同一成员，避免跨成员泄露内容是否存在。

### 7.2 临时文件与断电恢复

每文件使用一个 `.part`，不保存几千个永久块再拼接；临时目录放在最终原件的同一存储卷上。块校验失败或请求中断，回退至最后 confirmed_offset；回退失败则将会话标记损坏，停止使用。

启动时先恢复会话再接收新写入：文件比 confirmed_offset 长则截断多余尾部；短于 confirmed_offset 或不存在则标记需重建，不向客户端谎报已保存的进度。数据库记录与文件系统不能跨两者原子提交，必须有明确恢复流程。

完整校验后先持久化 COMMITTING 记录及目标 asset_id/path，再同卷移动原件，最后事务标记 READY、写来源关系、排预览任务。移动后数据库事务失败，启动时根据 COMMITTING 验证目标文件并补齐；失败保留待核对，不静默覆盖或删除原件。成功回复包含 asset_id、大小、SHA256 和确认状态。

SQLite 事务/文件刷新使用要求持久化的设置；断电验收还需实际设备测试，不能把 API 返回成功等同于所有磁盘缓存已经具备绝对断电保障。

### 7.3 取消与会话过期

暂停保留 confirmed_offset 与容量预留；取消为可恢复的任务状态，是否删除临时文件由服务端维护策略决定。建议暂停会话默认保留 7 天，过期前显示提示，可延长。清理临时文件不触碰 READY 原件；过期任务重新上传需新会话。

## 8. 原件布局、去重与容量

示例目录（名称为设计建议）：

```text
FamilyNas/
  NasServer.exe
  config/server.json
  web/
  data/
    catalog.db
    storage/<member-id>/originals/2026/11/<asset-id>.jpg
    storage/<member-id>/uploads/<upload-id>.part
    cache/thumbnails/
    cache/video/
    trash/
  logs/
```

文件路径使用服务器生成的 ID，原始文件名保存在数据库并用于下载的 Content-Disposition。客户端不能指定物理路径；扩展名、日期和 MIME 是元数据，需校验/规范化，不用于信任或执行文件。

日期优先采用可解析的原始拍摄时间，同时保存时区及时间来源；缺失时回退到来源提供的时间或导入时间。不能仅根据一个不存在时区的 EXIF 时间猜定真实时区。原图方向保存在原件中，缩略图统一按 EXIF 方向显示。

同成员同摘要大小对应一个物理原件，多个手机来源关联到同一 asset；同名不同内容保留两份。不同成员首版独立存储。来源映射丢失可重新对账，不导致原件被回收。

双手机可能同时完成同一内容上传，因此提交阶段需按 owner+摘要+大小互斥，并由数据库唯一约束兜底；后完成者复用已提交原件、写入自己的来源关系并返回同一 asset_id，确认映射成功后再回收自己的临时文件，不能留下第二个标为READY的原件或误删胜出文件。

容量管理同时计算已提交原件、缓存、未完成会话剩余预留与磁盘安全余量，并动态检查实际可用空间。建议保留可配置最小余量，拒绝超配新会话；预留不是操作系统硬配额，写盘仍需正确处理其他程序占满磁盘。

原始 HEIC/RAW/Motion Photo 等可先作为不改写的文件备份，预览是否支持单独展示；首版不承诺所有动态照片、外置 sidecar 配对与厂商私有格式的完整播放体验。视频原件保持原编码，浏览器不支持时提示下载或排队生成兼容预览。

## 9. 元数据与作业模型

| 表 | 关键职责 |
| --- | --- |
| members | 成员与权限归属 |
| devices / credentials | 设备身份、所属成员、授权状态与凭据撤销 |
| assets | asset_id、owner、SHA256、size、原件位置、内容类型、时间、COMMITTING/READY/异常状态 |
| sources | device + 本地来源键/版本 到 asset 的映射、原名/相册、备份确认时间 |
| uploads | 客户端任务 ID、owner、期望摘要/大小、confirmed_offset、临时与目标位置、状态、过期时间 |
| jobs | 缩略图/封面/预览/完整性巡检，重试次数、下次执行、错误分类与租约 |
| events | 连接、失败、入库、删除/恢复等摘要；不记录令牌或原文件内容 |

约束包括 owner+客户端任务 ID 唯一、同 owner 的 READY 内容摘要/大小去重、来源版本防重复、每会话单写者。SQLite 写事务保持短小；大文件校验和网络等待不持有数据库写锁。

原件 READY 后再运行低优先级预览任务。任务具有租约，进程退出后可回收重新排队；输出也用临时文件与校验后提交。预览失败不会把已完整入库的备份标成上传失败。

## 10. 核心 API 草案

| API | 作用 |
| --- | --- |
| GET /api/v1/server | 有限的协议版本/身份/健康状态；不公开私人媒体与完整配置 |
| POST /api/v1/login | 用户名密码登录，返回Cookie；原生客户端可显式取得Bearer令牌 |
| GET/POST /api/v1/users | 管理员列出或创建账号 |
| POST /api/v1/users/{id} | 管理员调整角色、启停及重置密码 |
| POST /api/v1/uploads | 幂等创建/取得上传会话；可能返回已有 asset |
| GET /api/v1/uploads/{id} | 状态、确认偏移、块大小、过期时间 |
| PUT /api/v1/uploads/{id}/data | 带偏移和块摘要的二进制块上传 |
| POST /api/v1/uploads/{id}/complete | 完整校验并提交；重复调用返回相同结果 |
| POST /api/v1/uploads/{id}/pause | 暂停会话并保留可续传数据 |
| GET /api/v1/assets | 游标分页，按成员/日期/类型/来源过滤 |
| GET /api/v1/assets/{id}/original | 授权下载/Range读取，不暴露物理路径 |
| GET /api/v1/assets/{id}/thumbnail | 授权预览，不存在时返回明确待生成状态 |
| GET /api/v1/tasks | 手机/管理端查询分页任务和状态 |
| GET /api/v1/admin/storage | 管理员查看容量、预留、临时文件和缓存 |

状态包括 401/403、409 偏移冲突、413 块过大、422 摘要不符、429 并发上限、507 空间不足。错误返回稳定 code、中文说明和可重试标记，不直接返回内部路径或堆栈。offset/size 在原生两端为64位整数；传入网页的JSON使用十进制字符串表示这些字段并校验范围，避免JavaScript Number精度问题。提交/校验采用作业状态返回，避免完整大视频校验跨越一个长 HTTP 请求。

## 11. 手机后台调度

- 自动增量：WorkManager 安排可中断的扫描/小批量上传，按网络/电量条件执行；每次处理有预算，后续继续排队。
- 用户点击立即备份：Android 14+ 评估 UIDT job；旧版本使用符合该系统限制的前台传输方式，持续显示可暂停通知。
- WorkManager 长期前台 Worker 在 Android 16 存在作业配额限制，因此不能让全部历史备份永远依赖一个 Worker。UIDT 需要用户发起，不能冒充自动后台任务。
- Wi-Fi 与“非计费网络”不是同义词；局域网使用先判断允许的传输类型并尝试服务器连接，不能要求该 Wi-Fi 一定能访问互联网。
- 手机强制停止、撤销权限、系统回收、重启都需要有明确状态。数据库任务可恢复不等于系统必定立即启动应用；再次打开应用触发对账和补传。

参考：[Android UIDT](https://developer.android.com/develop/background-work/background-tasks/uidt)、[长时间 Worker 与 Android 16 配额](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)、[MediaStore](https://developer.android.com/training/data-storage/shared/media)、[部分媒体授权](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)。

## 12. 管理界面与状态表达

电脑导航：首页、照片/视频、设备与成员、备份任务、存储、设置。首页显示已入库数量/容量、手机等待数、活跃上传、预留空间与错误；任务按“待上传/上传中/校验中/已入库/预览生成中/等待电脑/等待授权/异常”等真实阶段展示。

手机导航：照片、备份、设备/设置。备份页显示授权范围、选中相册、上次成功对账时间、待处理数量、已确认字节、立即备份/暂停。进度不要因为本地 socket 已发送就显示100%完成；服务器入库确认与预览进度分开。

预览列表使用游标分页、缩略图懒加载、限制缓存和虚拟列表；图片/视频请求离开页面可取消。第一版可按秒级轮询任务摘要，不在 httplib 上传线程池中占满长连接。

## 13. 保留、恢复与第二份副本

手机删除、相册移动、撤销设备均不删除服务器原件。首版不自动清理手机空间。

服务器删除设计为单独的管理员操作，先逻辑回收站，再按保留期清理；多个来源引用的原件不能因一个来源删除而移除。真正物理清理必须检查引用、作业与回收站状态。

“已备份到电脑”“预览可用”“已验证第二份副本”分别展示。首版保证电脑副本的接收与恢复闭环，第二块盘副本任务后续接入；一块电脑硬盘不提供坏盘后的恢复能力。

恢复需同时保留原件和目录数据库，提供 SQLite Backup API 或正确 checkpoint/停写后的数据库备份，不能运行中只复制 catalog.db 而遗漏 WAL。派生缩略图可重建。提供文件清单与校验报告，校验异常不自动删除证据文件。

## 14. 性能起点与验收

性能先测网络吞吐、手机读盘/摘要、服务器写盘、完整校验和缩略图各阶段。初版手机先算完整 SHA256 再上传，服务端最终复读校验，可靠但有额外读盘成本；记录后再优化连续会话的增量摘要路径，仍保留恢复后的全量核对，不承诺零额外 I/O。

首版验收至少覆盖：

1. 同名不同内容、同内容不同名、双手机重复照片与成员隔离。
2. 混合照片与超过4GiB视频，不依赖任何32位长度；中文、空格、特殊字符和长文件名。
3. 每块中断、ACK丢失、上传complete重复、手机/电脑重启，最终摘要一致且无重复入库。
4. COMMITTING 各阶段注入崩溃，恢复后不显示丢失的原件为 READY。
5. 磁盘写满、目录无权限、数据盘断开、块/整文件摘要错误，保留原件与可诊断状态。
6. 权限仅部分授权、撤销权限、图库变化、后台限制、锁屏、省电、强制停止后重开；记录每机型实际表现。
7. 关闭/重开WebView不丢任务；普通远程页面无法调用NAS原生备份接口。
8. 原图EXIF方向、视频拖动播放与Range、预览失败重试、电脑副本下载后完整摘要核对。
9. 设备撤销后无法上传/读取，成员不能访问其他成员对象，客户端路径不能逃逸存储根目录。
10. 真实恢复演练：新服务器环境载入数据库/原件，手机重新登录并对账；不要只验证“上传成功”。

## 15. 实现顺序

里程碑 A：C++服务、账号登录/角色、网页、手动前台上传、断点与完整摘要、下载恢复。

里程碑 B：NAS Runtime、媒体授权/扫描、持久化任务、原生传输、限量自动备份、用户长任务、真机恢复测试。

里程碑 C：相册时间线/视频封面、设备与成员管理、预览缓存、容量管理、服务自启动与完整交付。

后续：第二硬盘副本、完整性巡检、可信局域网发现；外网通过独立接入设计增加TLS/访问控制/代理支持，不直接默认开启端口映射。

验收版本必须包含网页资源、运行所需DLL/证书配置、数据库迁移、VS2022方案、固定依赖与许可证、APK与签名升级说明。用户APK签名身份不进入公开源码包。

执行优先级：先让自己的电脑与手机完成上传、续传、校验和恢复，再完善自动备份与日常浏览。上述故障恢复测试服务于数据可靠性，保留为核心验证；开源展示、双语文档、自动发行和更多平台适配不作为这些功能的前置条件。
